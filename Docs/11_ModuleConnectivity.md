# TDD-11. Связность отсеков

## 1. Геометрическое соседство

Два модуля геометрически соседствуют, если хотя бы
одна клетка первого модуля имеет общую сторону
с клеткой второго модуля.

Диагональное касание соседством не считается.

## 2. Общая граница

GridBoundarySegment описывает границу между двумя
соседними клетками.

Порядок клеток не влияет на идентичность границы.

Это позволяет позднее привязывать к конкретной границе:

- дверь;
- люк;
- лестницу;
- лифт;
- герметичную переборку;
- разрушенный проход.

## 3. Модули разных размеров

ModuleAdjacency хранит все единичные участки общей границы.

Например, два модуля высотой в две клетки могут иметь
два общих участка стены.

## 4. Направление

Направление задаётся относительно исходного модуля:

- Left;
- Right;
- Down;
- Up.

Обратный запрос возвращает противоположное направление.

## 5. Соседство не является проходимостью

Общая стена не создаёт автоматический проход.

Горизонтально соседние отсеки потребуют дверь
или другой совместимый переход.

Вертикально соседние отсеки потребуют люк,
лестницу или лифт.

## 6. Реализованный API

BastionGrid и Bastion предоставляют:

- TryGetModuleAdjacencies;
- TryGetModuleAdjacency.

Для существующего изолированного модуля возвращается
успешный результат с пустым списком.

Для отсутствующего модуля возвращается false.

## 7. Следующий подэтап

Следующий подэтап должен добавить явные переходы:

- тип перехода;
- занимаемую границу;
- направление использования;
- состояние;
- возможность блокировки;
- проверку совместимости.

Только после этого будет создан граф проходимости.

## 8. Явные переходы

ModulePassage представляет конкретную конструкцию,
установленную на одном GridBoundarySegment.

Поддерживаются:

- Door;
- Hatch;
- Ladder;
- Stairway;
- Elevator.

Горизонтальная граница поддерживает Door.

Вертикальная граница поддерживает Hatch, Ladder,
Stairway и Elevator.

## 9. Направление

Переход может быть:

- Bidirectional;
- SourceToTargetOnly;
- TargetToSourceOnly.

Направление является конструктивным ограничением
и не учитывает текущее состояние перехода.

## 10. Состояние

Текущие состояния:

- Open;
- Closed;
- Locked;
- Blocked;
- Destroyed.

Состояние пока не преобразуется напрямую
в итоговую проходимость.

Например, уничтоженная дверь и уничтоженный лифт
могут иметь разные последствия.

## 11. Целостность

На одном единичном участке границы может находиться
не более одного прохода для перемещения бригад.

Между двумя крупными модулями может существовать
несколько переходов на разных участках общей границы.

Удаление модуля удаляет все связанные переходы.

## 12. Следующий подэтап

Подэтап 11.3 должен добавить:

- PassageTraversalContext;
- PassageTraversalPolicy;
- диагностические причины блокировки;
- граф доступных переходов;
- учёт направления и состояния;
- точки расширения для энергии, контроля, дыма,
  пожара и повреждений.
