# TDD-11. Связность отсеков

## 1. Геометрическое соседство

Два модуля геометрически соседствуют, если хотя бы
одна клетка первого модуля имеет общую сторону
с клеткой второго модуля.

Диагональное касание соседством не считается.

## 2. Общая граница

GridBoundarySegment описывает границу между двумя
соседними клетками.

Порядок клеток не влияет на идентичность границы.

Это позволяет позднее привязывать к конкретной границе:

- дверь;
- люк;
- лестницу;
- лифт;
- герметичную переборку;
- разрушенный проход.

## 3. Модули разных размеров

ModuleAdjacency хранит все единичные участки общей границы.

Например, два модуля высотой в две клетки могут иметь
два общих участка стены.

## 4. Направление

Направление задаётся относительно исходного модуля:

- Left;
- Right;
- Down;
- Up.

Обратный запрос возвращает противоположное направление.

## 5. Соседство не является проходимостью

Общая стена не создаёт автоматический проход.

Горизонтально соседние отсеки потребуют дверь
или другой совместимый переход.

Вертикально соседние отсеки потребуют люк,
лестницу или лифт.

## 6. Реализованный API

BastionGrid и Bastion предоставляют:

- TryGetModuleAdjacencies;
- TryGetModuleAdjacency.

Для существующего изолированного модуля возвращается
успешный результат с пустым списком.

Для отсутствующего модуля возвращается false.

## 7. Следующий подэтап

Следующий подэтап должен добавить явные переходы:

- тип перехода;
- занимаемую границу;
- направление использования;
- состояние;
- возможность блокировки;
- проверку совместимости.

Только после этого будет создан граф проходимости.

## 8. Явные переходы

ModulePassage представляет конкретную конструкцию,
установленную на одном GridBoundarySegment.

Поддерживаются:

- Door;
- Hatch;
- Ladder;
- Stairway;
- Elevator.

Горизонтальная граница поддерживает Door.

Вертикальная граница поддерживает Hatch, Ladder,
Stairway и Elevator.

## 9. Направление

Переход может быть:

- Bidirectional;
- SourceToTargetOnly;
- TargetToSourceOnly.

Направление является конструктивным ограничением
и не учитывает текущее состояние перехода.

## 10. Состояние

Текущие состояния:

- Open;
- Closed;
- Locked;
- Blocked;
- Destroyed.

Состояние пока не преобразуется напрямую
в итоговую проходимость.

Например, уничтоженная дверь и уничтоженный лифт
могут иметь разные последствия.

## 11. Целостность

На одном единичном участке границы может находиться
не более одного прохода для перемещения бригад.

Между двумя крупными модулями может существовать
несколько переходов на разных участках общей границы.

Удаление модуля удаляет все связанные переходы.

## 12. Следующий подэтап

Подэтап 11.3 должен добавить:

- PassageTraversalContext;
- PassageTraversalPolicy;
- диагностические причины блокировки;
- граф доступных переходов;
- учёт направления и состояния;
- точки расширения для энергии, контроля, дыма,
  пожара и повреждений.

## 13. Политика проходимости

Физическое состояние перехода не преобразуется
в проходимость внутри ModulePassage.

Для этого используется IModulePassageTraversalPolicy.

Базовая политика учитывает:

- разрешённое направление;
- Open;
- Closed;
- Locked;
- Blocked;
- Destroyed.

Open разрешает движение.

Остальные состояния в базовой политике блокируют движение.

## 14. Контекст прохода

ModulePassageTraversalContext содержит:

- переход;
- исходный модуль;
- целевой модуль.

Это позволяет будущим политикам учитывать:

- питание лифта;
- контроль отсеков;
- пожар;
- дым;
- герметизацию;
- особенности конкретной бригады.

## 15. Граф

ModuleConnectivityGraph является неизменяемым снимком.

Каждый доступный переход представлен направленным ребром.

Двусторонний переход создаёт два ребра.

Односторонний переход создаёт одно ребро.

Недоступный переход не создаёт ребра.

Изолированные модули остаются узлами графа.

После изменения состояния перехода граф следует
построить повторно.

## 16. Границы текущего подэтапа

Граф показывает доступные непосредственные переходы.

Он пока не ищет полный маршрут между двумя модулями.

Поиск маршрута и диагностика отсутствия пути
относятся к подэтапу 11.4.

## 17. Маршрут

ModuleRoute является неизменяемым снимком
кратчайшего доступного маршрута.

Маршрут содержит:

- исходный модуль;
- целевой модуль;
- последовательность шагов;
- последовательность посещаемых модулей;
- количество необходимых переходов.

Один шаг соответствует одному ModulePassage.

Маршрут из модуля в него же является успешным
пустым маршрутом.

## 18. Алгоритм

Используется поиск в ширину.

Он выбирает маршрут с минимальным количеством
непосредственных переходов между отсеками.

Порядок обхода фиксирован, поэтому одинаковое
входное состояние создаёт одинаковый маршрут.

## 19. Диагностика

Различаются:

- SourceModuleNotFound;
- TargetModuleNotFound;
- NoStructuralConnection;
- TraversalBlocked.

NoStructuralConnection означает отсутствие
непрерывной цепочки физических переходов.

TraversalBlocked означает, что цепочка существует,
но направление или состояние переходов блокирует путь.

Для TraversalBlocked возвращаются препятствия
на границе достижимой области.

## 20. Повторная проверка

Маршрут является результатом планирования.

Изменение состояния двери, люка, лестницы или лифта
не изменяет уже созданный объект маршрута.

Перед выполнением каждого шага условия должны быть
проверены повторно исполнителем приказа.
