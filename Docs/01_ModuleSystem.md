# TDD-01. Система модулей

## 1. Назначение системы

Бастион строится из функционально законченных модулей-отсеков.

Игрок не занимается размещением отдельных станков, двигателей, кроватей,
шкафов и инструментальных стоек внутри отсека. Их наличие считается частью
конструкции выбранного модуля и выражается его характеристиками.

Примеры модулей:

- машинный отсек;
- ремонтный отсек;
- склад боеприпасов;
- командный отсек;
- медицинский отсек;
- жилой отсек;
- вентиляционный отсек;
- орудийная платформа;
- лестничный отсек;
- проход.

## 2. Основные сущности

### ModuleDefinition

Неизменяемое описание модуля из игрового каталога.

Содержит:

- уникальный идентификатор;
- название;
- категорию;
- функциональный тип;
- размер на сетке;
- массу;
- стоимость;
- максимальную прочность;
- пороги повреждения;
- потребление энергии;
- выделение тепла;
- требования к обслуживающему персоналу;
- список функциональных особенностей.

Один `ModuleDefinition` может использоваться любым количеством установленных
в бастионе модулей.

### ModuleInstance

Конкретный модуль, установленный в конкретном бастионе.

Содержит изменяемое состояние:

- уникальный идентификатор экземпляра;
- ссылку на ModuleDefinition;
- позицию на сетке;
- текущую прочность;
- техническое состояние;
- контроль над отсеком;
- назначенные бригады;
- временные эффекты и неисправности.

### ModuleFeature

Описание специальной функции модуля.

Примеры:

- производство лошадиных сил;
- производство энергии;
- хранение боеприпасов;
- ремонтная поддержка;
- лечение раненых;
- размещение экипажа;
- вентиляция;
- управление вооружением.

Игрок по-прежнему размещает один готовый отсек. `ModuleFeature` используется
только внутри архитектуры и не превращается в отдельное оборудование
для микроменеджмента.

## 4. Общие характеристики модуля

Каждый модуль имеет:

- Id;
- Name;
- Category;
- Type;
- GridSize;
- MassKg;
- Cost;
- MaxDurability;
- DamagedDurabilityThreshold;
- CriticalDurabilityThreshold;
- IdlePowerConsumption;
- ActivePowerConsumption;
- HeatGeneration;
- CrewRequirement;
- Features.

Внешняя броня не является характеристикой отсека.

Бронирование корпуса и внутренние модули являются разными слоями симуляции.
Попадание сначала взаимодействует с броневой секцией, а затем с расположенными
за ней отсеками.

## 5. Требования к персоналу

Для модуля задаются:

- MinimumPersonnel;
- OptimalPersonnel;
- MaximumPersonnel.

Меньше минимального количества:

- модуль не работает;
- либо выполняет только разрешённые аварийные функции.

От минимального до оптимального:

- производительность растёт вместе с численностью.

От оптимального до максимального:

- дополнительный персонал даёт уменьшающийся прирост.

Больше максимального количества:

- возникает переполнение;
- люди мешают друг другу;
- эффективность перестаёт расти или снижается.

В один модуль разрешено назначать несколько бригад.

Итоговая эффективность позднее будет учитывать:

- общую численность;
- соответствие специализации;
- опыт;
- мораль;
- усталость;
- техническое состояние модуля;
- наличие энергии;
- наличие необходимых ресурсов.

## 6. Категории и типы

Категория используется для группировки в конструкторе.

Примеры категорий:

- конструкция;
- движение;
- энергетика;
- вооружение;
- логистика;
- ремонт;
- командование;
- жизнеобеспечение;
- медицина;
- вспомогательные системы.

Тип описывает основное назначение модуля.

Примеры типов:

- MachineRoom;
- RepairBay;
- AmmoStorage;
- CommandPost;
- CrewQuarters;
- Ventilation;
- WeaponPlatform;
- MedicalBay;
- Corridor;
- Stairwell.

Конкретные варианты модулей не являются уровнями улучшения.

Не используется схема:

- базовый;
- улучшенный;
- элитный.

Вместо этого каталог содержит разные инженерные решения со своими
преимуществами и недостатками.

## 7. Техническое состояние

Техническое состояние определяется текущей прочностью:

- Operational;
- Damaged;
- Critical;
- Destroyed.

Пороги задаются в ModuleDefinition, поскольку разные модули могут по-разному
реагировать на повреждения.

Техническое состояние не равно работоспособности.

Исправный модуль также может не работать из-за:

- отсутствия экипажа;
- отсутствия энергии;
- отсутствия боеприпасов или топлива;
- перегрева;
- блокировки проходов;
- вражеского контроля.

## 8. Контроль над отсеком

Контроль хранится независимо от технического состояния:

- Friendly;
- Contested;
- Occupied.

Захваченный отсек может оставаться технически исправным.

После занятия отсека противник может:

- закрепиться;
- продолжить продвижение;
- подготовить диверсию;
- вывести оборудование из строя.

Такие действия требуют отдельных ходов.

## 11. Первые функциональные особенности

На текущем этапе реализованы:

### PropulsionFeatureDefinition

Используется машинными отсеками.

Содержит:

- HorsePower;
- FuelConsumptionPerTurn;
- BaseWearPerTurn.

### RepairSupportFeatureDefinition

Используется ремонтными отсеками.

Содержит:

- RepairPointsPerTurn;
- MaximumConcurrentJobs;
- SparePartsCapacityUnits.

Ремонтная мастерская создаёт ремонтную мощность для всего бастиона,
но фактический ремонт зависит от доступного маршрута, бригад,
запасных частей и состояния повреждённого отсека.

### AmmoStorageFeatureDefinition

Используется складами боеприпасов.

Содержит:

- CapacityVolumeUnits;
- OutputThroughputPerTurn.

Вместимость выражается в единицах объёма. Разные боеприпасы
в дальнейшем будут занимать разный объём.

## Модернизации и автоматизация

Модернизация не является абстрактным уровнем качества.

Каждая модернизация должна описывать конкретное
инженерное изменение:

- требования совместимости;
- занимаемый объём;
- добавленную массу;
- энергопотребление;
- тепловыделение;
- сложность ремонта;
- влияние на надёжность;
- изменение потребности в персонале;
- новые функциональные возможности;
- технические ограничения.

Автоматизация применяется только к конкретным видам работ.

Она не может уменьшать кадровые требования,
если конструкция модуля физически не поддерживает
соответствующие автоматические механизмы.

Примеры допустимой автоматизации:

- автомат заряжания;
- электрические приводы наведения;
- дистанционное управление;
- автоматизированная система пожаротушения;
- автоматическая диагностика;
- радиолокационное сопровождение целей.

Примитивное ручное орудие не становится автоматическим
только из-за установки универсального улучшения.

Для его автоматизации потребуется фактически добавить:

- механизм заряжания;
- приводы наведения;
- систему управления огнём;
- питание;
- датчики;
- совместимую конструкцию боеприпасов.

Каталог модернизаций не должен использовать градацию:

- дешёвая;
- улучшенная;
- элитная.

Каждая модернизация должна представлять отдельный
инженерный компромисс.
