# TDD-03. Модель бастиона

## 1. Назначение

`Bastion` является главной доменной сущностью модульной боевой машины.

Он владеет сеткой размещения и предоставляет операции:

- установки модулей;
- удаления модулей;
- поиска модулей;
- расчёта совокупных характеристик конструкции.

Внешний код не должен самостоятельно поддерживать отдельные списки
модулей параллельно с `BastionGrid`.

## 2. Идентичность

Бастион имеет:

- постоянный Guid;
- название;
- ширину сетки;
- количество этажей.

Возможность передать существующий Guid необходима для будущей
загрузки сохранённой кампании.

## 3. Проектные характеристики

`BastionDesignStatistics` описывает установленную конструкцию.

В расчёт входят:

- количество модулей;
- количество занятых клеток;
- масса;
- стоимость;
- суммарная максимальная прочность;
- энергопотребление;
- выделение тепла;
- требования к экипажу;
- номинальная мощность машинных отсеков.

Проектная статистика не зависит от текущих повреждений.

Уничтоженный модуль:

- продолжает занимать пространство;
- продолжает иметь массу;
- остаётся частью стоимости проекта;
- сохраняет номинальные характеристики в проектной статистике.

## 4. Текущая эффективность

Фактическая работоспособность машины будет рассчитываться отдельно.

На неё будут влиять:

- техническое состояние отсеков;
- назначенные бригады;
- опыт и численность бригад;
- наличие энергии;
- наличие топлива;
- перегрев;
- снабжение;
- контроль над отсеками.

Для этого позднее будет создана отдельная модель
операционных характеристик.

## 5. Направление зависимостей

`Bastion` использует `BastionGrid`.

`BastionGrid` не должен знать о:

- суммарной массе;
- общей стоимости;
- мощности двигателей;
- бригадах;
- кампании;
- пользовательском интерфейсе.

Сетка отвечает только за пространственную целостность конструкции.
