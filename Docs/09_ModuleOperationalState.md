# TDD-09. Операционное состояние модулей

## 1. Назначение

Операционная оценка определяет способность модуля
выполнять активную работу в текущий момент.

Она объединяет:

- техническое состояние;
- контроль над отсеком;
- фактически предоставленный режим питания;
- эффективность назначенных бригад;
- переполнение.

## 2. Порядок расчёта

Перед операционной оценкой должно быть выполнено
распределение энергии:

1. игрок задаёт RequestedPowerMode;
2. вызывается ResolvePowerDistribution;
3. определяется EffectivePowerMode;
4. рассчитывается эффективность бригад;
5. рассчитывается операционная эффективность.

## 3. Повреждения

Прототипные множители:

- Operational: 1.00;
- Damaged: 0.75;
- Critical: 0.40;
- Destroyed: 0.00.

Damaged и Critical не обязательно полностью блокируют работу.

Destroyed всегда блокирует работу.

## 4. Блокирующие причины

Активная работа невозможна, если:

- модуль уничтожен;
- отсек не контролируется игроком;
- модуль не получил Active-питание;
- не выполнены минимальные кадровые требования.

Повреждение и переполнение снижают эффективность,
но не обязательно останавливают модуль.

## 5. Механические системы без энергопотребления

Модуль с нулевым энергопотреблением всё равно имеет
RequestedPowerMode и EffectivePowerMode.

Для выполнения активной работы он должен быть переведён
в Active.

Энергетическая система предоставит ему Active без затрат энергии.

Это позволяет вручную отключать даже полностью механические
установки без создания отдельных правил.
